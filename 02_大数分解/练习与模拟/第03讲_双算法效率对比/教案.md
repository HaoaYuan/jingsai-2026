# 第 03 讲教案 · 双算法效率对比

> 班型：初中组备赛队（完全零基础，已完成第 01、02 讲）
> 课时：40 分钟；配套课件 `课件.pptx`、练习页 `练习.html`
> 本讲与第 04 讲合对准评分表「算法效率探究与优化 20 分」的前半场：三版试除逐版详解 + 实验一（单个数三档计时）

## 教学目标

1. 能独立写出并讲清三种试除算法（朴素 / 优化 √N 跳偶 / 6k±1），说清每一处改动「为什么这样改」。
2. 会用 `time.perf_counter()` 计时（重复 3 次取最小、限时超时如实记录），完成实验一三档实测并填记录表实验一部分。
3. 能按「条件 + 数据 + 原因」模板口头说出一句实验结论（书面结论句工坊在第 04 讲）。

## 重点难点

- 重点：三版算法的「改动链条」--每一版只改上一版的 1–2 处，每处改动都有图解支撑。
- 难点：√N「因子成对」为什么成立；6k±1 为什么只剩两种位置、为什么一轮必须查两个位置（49 = 7 × 7 靠 i + 2 抓到）。
- 认知负荷控制：本讲只讲实验一（单个数）；三版共用同一根代码逐版改，一次只改一处；批处理与埃氏筛整体放到第 04 讲。

## 课前准备

- 每机：`练习.html`、`代码/素性检查.py`、`代码/实验一_三版试除.py`、打印 `数据/实验记录表.md` 每队一份。

## 分步教学脚本（三版逐版详讲，教师带打）

第 1 版朴素（4–12 分钟）：`i = 2` 起步，`while i < n:` 全都试，`n % i == 0` 就下结论。带学生现场跑 1000003（约 0.09 秒），再问：10^12 的数呢？--引出「候选太多」是唯一病因。

第 2 版优化（12–20 分钟），一次只改一处：
- 改动 ①（循环条件）：投影 36 的因数成对表，得出「查到 √N 就查完了」→ 把 `while i < n:` 改成 `while i * i <= n:`，先跑一遍看对不对。
- 改动 ②（跳偶）：投影跳偶图解（奇数没有偶数因子）→ 加特判 2，步长改 `i = i + 2`，再跑。
- 两步各自独立验证--「一次只改一处」本身就是要教的实验纪律。

第 3 版 6k±1（20–27 分钟）：
- 数轴图解：3,5,7,9,11,13… 中 9,15,21 是 3 的倍数、必已被 3 除过 → 候选只剩 6k−1 与 6k+1 两种位置。
- 三处小改：特判 3、每轮查 `n % i == 0 or n % (i + 2) == 0`、`i = i + 6`。
- 追问边界：49 = 7 × 7 谁抓到？（i = 5 时查 i + 2 = 7）25 = 5 × 5 呢？（i = 5 第一查）

## 板书设计

```
三版一条链（同一根代码逐步改）
v1 朴素：while i < n              ← 全都试
v2 优化：while i * i <= m + i+=2  ← 查到 √N、跳过偶数
v3 6k±1：查 i 和 i+2、i+=6        ← 剩两种位置
计时三规矩：perf_counter | 3 次取最小 | 超时如实记
结论三要素：条件 + 数据 + 原因
```

## 实验设计要点（为什么这样设计）

1. **同任务**：三版判断的是同一个数、输出同一结论--评委问「比的是不是同一件事」时有底。
2. **档位选质数**：质数要把候选除满才能下结论，最能拉开版本差距（合数会被中途因子提前打断）。
3. **超时是数据**：朴素版 30 秒未出结果如实记录--评分表要「客观记录程序耗时」，超时记录完全合格。
4. **本机实测参考值**（2026-11-10）：见 `数据/实验记录表.md`；机房不同配置有差异，**课堂上必须以现场实测为准**，报告里注明环境。

## 常见错误表

| 现象 | 原因 | 纠正 |
|---|---|---|
| 计时结果每次差很多 | 只跑了一次，撞上系统卡顿 | 重复 3 次取最小 |
| 两版数字不一样还写结论 | 没控制变量 | 同一组数字重跑 |
| 把超时写成「程序坏了」 | 不理解客观记录 | 超时也是数据：如实写「>30 秒未出结果」 |
| 优化版写成了朴素版逻辑 | 忘了跳偶或忘了 i*i<=n | 对照 T1 starter 检查循环条件 |
| 6k±1 漏判 25（5 的平方） | 只检查 i 不检查 i+2 | 一轮检查 i 和 i+2 两个位置 |
| 程序停不下来（死循环） | 6k±1 版忘加特判 3，i 永远撞 3 的倍数 | 特判在前、步长在后，对照 T2 starter |
| 结论句只有「快多了」 | 缺数据缺条件 | 按三要素模板重写 |
