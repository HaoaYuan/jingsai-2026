# 流程图规范与示例（第 05 讲 · 评分表「问题描述 10 分」）

> 评分表原文：能用流程图、伪代码或文字清晰描述**输入数据、分解规则、数据范围、统计口径、输出格式和边界条件**；能将实际数学问题转化为可计算的算法模型。
> 现场是手画（草稿纸）或 PPT 里画，工具不重要，符号规范才重要。

## 四种标准符号（GB/T 1526 常用子集）

| 符号 | 形状 | 用途 | 例子 |
|---|---|---|---|
| 起止框 | 圆角矩形 | 开始 / 结束 | 「开始」「结束」 |
| 输入输出框 | 平行四边形 | 读数据 / 输出结果 | 「输入 n」「输出 i」 |
| 判断框 | 菱形 | 是 / 否 分支 | 「n % i == 0 ?」 |
| 处理框 | 矩形 | 计算、赋值 | 「m = m // i」 |

连接线带箭头，判断框的两个出口必须标「是 / 否」。一张图里同一任务只用一条主线，不画双箭头。

## 完整示例：优化试除判质数（照这个规范画）

```text
(开始)
   │
[输入 n]                          ← 平行四边形
   │
<n == 2?> ──是──→ [输出 yes] ──→ (结束)
   │否
<n % 2 == 0 且 n>2?> ──是──→ [输出 no] ──→ (结束)
   │否
[i = 3]
   │
<i × i <= n?> ──否──→ [输出 yes] ──→ (结束)
   │是
<n % i == 0?> ──是──→ [输出 no] ──→ (结束)
   │否
[i = i + 2]
   │
   └──────→ 回到「i × i <= n?」
```

画法三自检：
1. 每个判断框都有「是」「否」两个出口吗？
2. 输入 / 输出用了平行四边形、判断用了菱形吗？
3. 顺着箭头走一遍，能在脑内跑通 n = 2、4、9、1000000007 四个例子吗？

## 常见扣分点

| 扣分点 | 后果 |
|---|---|
| 判断框没标「是 / 否」 | 分支走向不明，评委追问 |
| 处理和判断混用形状 | 逻辑层次不清 |
| 漏「开始 / 结束」框 | 流程不完整 |
| 流程图与代码不一致（图上除到 n，代码除到 √n） | **严重**--「图码一致」是「算法设计与实现 20 分」的加分点 |
| 循环回跳箭头丢失 | 流程断裂 |

## 报告里怎么用

- PPT 第 3 页放主算法流程图（1 张即可，别堆 3 张）。
- 图旁配 1 句话：「图 1：优化试除判质数流程，仅遍历至 √N，操作次数从 O(N) 降至 O(√N)。」
- 伪代码和文字描述是等价替代（评分表原文「流程图、伪代码或文字」），但流程图最直观，建议至少有一张。
