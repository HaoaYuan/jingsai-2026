# 评分表自评清单（模拟演练与比赛收尾 10 分钟通用）

> 逐项打勾；任何一项「否」都意味着明确的失分点，时间允许就当场补。
> 依据：仓库根目录 `大数分解.doc` 评价参考表原文（7 项 100 分）。

## 1. 项目理解（10 分）：准确理解「大数分解与算法探究」的核心任务

- [ ] 能用一句话说出两道任务分别要什么
- [ ] PPT 第 1 页有题目的一句话理解

## 2. 问题描述（10 分）：输入、规则、范围、口径、输出格式、边界条件

- [ ] 草稿 / PPT 写全六要素
- [ ] 有一张规范流程图（或等价伪代码 / 文字），判断框标了「是 / 否」
- [ ] 流程图与代码一致（图上除到几，代码就除到几）

## 3. 数字分解与处理（15 分）：分解、成分提取、分类筛选、统计准确、输出完整规范

- [ ] 质因数分解式格式与题面逐字符一致（等号、乘号、空格）
- [ ] 指定成分（偶因数、奇因数和、最大质因数等）结果与程序实跑一致
- [ ] 质数边界输出正确（剩 m 本身也输出）
- [ ] 输出无多余空行、无末尾空格

## 4. 算法设计与实现（20 分）：正确、清晰、模块划分、可读可复用

- [ ] 两道任务的程序都实跑出正确结果
- [ ] 变量名可读、有中文注释、缩进统一 4 空格
- [ ] 重复逻辑有复用（如分解函数式的段落结构）
- [ ] 代码文件名符合现场要求，无乱码

## 5. 算法效率探究与优化（20 分）：多组测试、客观记录、控制变量、复杂度、数学原理、结论可信

- [ ] 至少两组实验，每组两个以上档位或规模
- [ ] 记录表填写完整（数字、版本、耗时、操作次数估算、结果）
- [ ] 控制变量三件套：同机、同组数字、同重复次数
- [ ] 复杂度写了时间 + 空间两栏
- [ ] 结论句三要素齐全（条件 + 数据 + 原因），数字全部来自实测
- [ ] 超时如实记录为「超时」，没有编数

## 6. 项目分析报告（20 分）：六要素 + 可视化 + 有条理

- [ ] PPT 覆盖：设计思路、算法原理、运行结果、效率对比、优化策略、创新点
- [ ] 至少 1 张流程图 + 1 张数据图表（不是全是文字或全是代码截图）
- [ ] 每页有一句加粗结论
- [ ] 图表数字与记录表一致

## 7. 现场成果分享（5 分）：陈述清晰、时间控制、答辩准确

- [ ] 两人都完整练过一遍 5 分钟陈述
- [ ] 每段有模板句，超时会自断跳收尾
- [ ] 问答 6 预案（埃氏筛为何快、数字怎么选、O(√N) 含义、还能怎么优化、边界处理、分工）都答得上来

## 提交清单（比赛通用）

- [ ] 代码文件命名符合现场要求
- [ ] 记录表 / 报告都在指定目录，能在断网状态下打开
- [ ] 没有把草稿、参考材料混进提交目录
