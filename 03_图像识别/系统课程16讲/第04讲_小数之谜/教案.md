## 教学目标

学完本课，学生应能：

1. 知道 `3.5`、`5.0` 这类带小数的数在 Python 里叫浮点数，是 `/` 的结果的常态。
2. 亲眼运行 `print(0.1 + 0.2)` 得到 `0.30000000000000004`，知道这是正常现象，不是电脑坏了。
3. 用「分一半」解释原因：`0.5`、`0.25`、`0.75` 能用二进制精确表示；`0.1` 在二进制里写不完（无限循环），Python 只能存最接近的数。
4. 说出 `0.1 + 0.2 != 0.3` 的完整因果：两个近似数各自带一点误差，相加后误差露馅。
5. 写出两种对策：`round(x, 2)` 用于显示；`abs(a - b) < 0.0001` 用于判断「足够接近」。
6. 知道 `print` 有时显示 `0.3` 是 Python 挑了最好看的写法，数本身仍不精确。

## 重点与难点

- **重点：**认得 `0.30000000000000004` 这个现象；会用 `round` 和差值比较两种对策。
- **难点：**接受「计算机存不准 0.1」——学生直觉认为计算机不会算错；理解二进制小数位是「一半、一半的一半」。
- **突破办法：**从 `0.5 = 一半`、`0.25 = 一半的一半` 入手，让学生在黑板上试着不断对半凑出 `0.1`，凑到写不下为止；再运行代码看到误差。

## 40 分钟流程

### 0–5 分钟：复习与预测（课件 1–3）

1. 复习第 3 课：`/` 的结果一律带小数，`10 / 2` 得 `5.0`。
2. 预测：投影 `print(0.1 + 0.2)`，几乎所有学生会答 `0.3`。
3. 运行，看到 `0.30000000000000004`。全班通常会有「电脑坏了」的反应。
4. 揭示本课目标：**不是电脑坏了，是小数在计算机里的存法有秘密；这节课搞懂它，还要学会两招自保。**

### 5–13 分钟：讲解与演示（课件 4–8）

教师现场操作，学生只看不敲。

1. **给名字：**带小数的数叫浮点数。`3.5`、`5.0`、`0.1` 都是。它就是上节课 `/` 给我们的那种数。
2. **计算机只认 0 和 1：**整数的二进制是 1、2、4、8 的组合；小数点后面的二进制，每一位是「一半、一半的一半、再一半」：`0.5`、`0.25`、`0.125`、`0.0625`……
3. **凑数游戏（板书）：**`0.5` 就是「一半」，能精确；`0.25` 是「一半的一半」，能精确；`0.75 = 0.5 + 0.25`，能精确。运行 `demo2_凑一半.py` 印证。
4. **凑 0.1：**`0.0625 + 0.03125 + 0.0078125 + …` 不断对半，黑板上写到第六七项，还差一点，永远差一点——`0.1` 在二进制里是无限循环小数，写不完。
5. **所以 Python 怎么办：**只存有限的位数，存「最接近 0.1 的那个数」。`0.1` 和 `0.2` 各自带一点点误差，加起来误差露馅，就是那串 `00000000000000004`。运行 `demo1_见一见.py`。
6. **为什么有时又显示 `0.3`：**Python 打印时会挑最短的写法「美化」给你看，数本身仍不精确。判断相等不能用 `==`。
7. **两招对策：**运行 `demo3_两个对策.py`——`round(a, 2)` 四舍五入到 2 位，用于显示；`abs(a - 0.3) < 0.0001` 差得足够小就算相等，用于比较。

### 30–37 分钟：人工智能知识与客观题（课件 12–13）

先用 3 分钟讲，再做课件里的 2–3 道题（6 道题全在课件 13–14 页，当堂先做第 1、3、5 题，其余课后）。

**讲稿：**

> 计算机的存储是有限的、离散的，就像我们的 0/1 网格把连续的图像切成一格一格。小数存不准，就是「有限的格子」装不下「无限的小数」。
>
> 人工智能到处都是小数：识别一张图的置信度是 0.97，模型的参数是几百万个小数。工程师每天都在跟这种小误差打交道，办法就是今天学的两招。看到 `0.30000000000000004` 不要慌——全世界所有编程语言都这样，这不是 bug，是计算机的诚实。

**当堂题（课件 13 页）：**

- 第 1 题：`print(0.1 + 0.2)` 输出什么？答案 B（`0.30000000000000004`）。
- 第 3 题：哪个数计算机能精确存储？答案 A（`0.5`）。
- 第 5 题：判断「足够接近」的正确写法？答案 B（`abs(a - 0.3) < 0.0001`）。
- 学生先答再翻页，请一名学生解释第 3 题为什么选 A。

### 37–40 分钟：离堂检查

- 上机一句话：运行 `print(0.1 + 0.2)`，口答它为什么不等 0.3（一句话：「0.1 在二进制里写不完，只能存最接近的，加起来误差露馅」）。
- 口头三连问：

  3. `round` 适合用来显示还是用来比较？

## 板书设计

```text
计算机只认 0 和 1
小数点后每一位 = 一半、一半的一半……
0.5 ✓   0.25 ✓   0.75 = 0.5 + 0.25 ✓
0.1 → 0.0625 + 0.03125 + 0.0078125 + … 凑不完 → 只能存最接近的

0.1 + 0.2 = 0.30000000000000004   （误差露馅，不是电脑坏了）
对策 1：round(x, 2)               （显示用）
对策 2：abs(a - b) < 0.0001       （比较用）
```

## 常见错误与纠正

| 现象 | 原因 | 纠正话术 |
|---|---|---|
| 学生认为「电脑坏了」「Python 有 bug」 | 不理解存储机制 | 不是 bug，所有语言都这样；计算机在诚实告诉你它的极限 |
| 抄结果时自己写成 `0.3` | 脑补输出 | 把 Shell 里的原样抄下来，一个字符都不改 |
| `if a == 0.3:` 永远不成立 | 浮点数不能直接比相等 | 用 `abs(a - 0.3) < 0.0001` |
| `abs` 拼成 `Abs` 或漏括号 | 函数名和语法不熟 | 报错看最后一行；`abs` 全小写 |
| `SyntaxError: invalid character '。'` | 中文句号当小数点 | 小数点也是英文符号 `.` |
| 以为 `round` 万无一失 | 不了解 round 也依赖存储值 | 运行任务 3 的 `round(2.675, 2)` 亲自看 |

## 参考答案

### 客观题（课件 13–14 页）

| 题号 | 答案 | 解析 |
|---:|---|---|
| 1 | B | 亲测输出 `0.30000000000000004`；A 是「想当然」，C、D 不成立。 |
| 2 | B | `0.1`、`0.2` 在二进制里是无限循环小数，只能存最接近的数，误差相加露馅；不是 Python 的 bug。 |
| 3 | A | `0.5` 恰好是二进制小数第一位「一半」，能精确表示；`0.1`、`0.2`、`0.3` 都写不完。 |
| 4 | A | `0.5` 和 `0.25` 都能精确表示，和 `0.75` 也精确，输出干净的 `0.75`。 |
| 5 | B | 浮点数比较用「差值足够小」；`==` 不可靠，C、D 与「接近」无关。 |
| 6 | A | `round(0.1 + 0.2, 2)` 四舍五入到 2 位，显示 `0.3`；它让结果「看起来干净」，判断相等仍建议用差值比较。 |

### 任务 1：见一见误差

```

### 任务 2：改对比较

```
